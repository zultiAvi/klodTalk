- CLI: `python -m server.tools.dedupe_events_jsonl [--base PATH] [--apply | --dry-run]`

- Atomic rewrite: backup to `events.jsonl.bak-<utc-iso>`, write `.tmp`, then
  `os.replace`. If a backup at the same second already exists, suffix `.N`.
- Per-file summary line: `<sid> kept=N dropped=M`.
- Aggregate summary at the end. Dry-run prints a reminder to re-run with
  `--apply` when duplicates were detected.

## Review Request

### Change Summary
Heals the user-visible "every message appears twice after reconnect" bug
introduced before commit 948633d. The fix has four parts:
1. Stops the only remaining active double-write site (nightly broadcast).
2. Closes a latent hook-event leak in the archive branch of
   `_session_to_dict` (low-impact today, but the symmetry was an open
   follow-up).
3. Adds an idempotent migration tool (`dedupe_events_jsonl.py`) that
   rewrites existing `events.jsonl` files in place — this is what actually
   removes duplicates from the user's affected machine, since 948633d is
   forward-only.
4. Adds a belt-and-braces client-side dedupe in the web client's history
   path, so any future server regression cannot resurface as user-visible
   duplicates.

### Files Modified
- server/server.py — drop `log_to_session=True` at nightly broadcast; add
  hook filter to archive branch of `_session_to_dict`.
- server/tools/__init__.py — new (empty, package marker).
- server/tools/dedupe_events_jsonl.py — new CLI utility.
- tests/test_session_log.py — two new regression tests.
- clients/web/index.html — dedupe `s.messages` in `case 'history'`.

### Self-Assessed Risk Areas
- `server/tools/dedupe_events_jsonl.py` rewrites on-disk JSONL. Default is
  dry-run; `--apply` is required to write. Backups are timestamped per file
  and never overwritten (suffix collision falls back to `.N`). Atomic
  rename via `os.replace`. Worst case is a stale backup on disk; data is
  preserved.
- The dedupe key `(timestamp, role, content, extra.type)` would in
  principle drop a legitimate duplicate if the user sent the exact same
  text in the same UTC iso-second AND no `extra.type` differs. This is the
  conscious tradeoff documented in the module docstring. Hook rows are
  exempt to keep their intentional repetition intact.
- The web-client dedupe in `case 'history':` uses the same key. Same
  tradeoff. Live `case 'new_message'` is untouched on purpose so legitimate
  same-second duplicates still render.
- Archive-branch hook filter: previously the code appended raw
  `json.loads(line)` to messages. Now we hold the parsed `row` in a
  variable so we can skip on `role == "hook"`. Output format unchanged for
  non-hook rows.

### Questions for Reviewer

  `python -m server.tools.dedupe_events_jsonl --apply` on the affected

- The dedupe key includes `extra.type`. If we ever start logging the same
