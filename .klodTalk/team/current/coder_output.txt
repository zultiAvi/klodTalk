Interactive-debug team implementation (Option A1 — reuse debugger broadcast role and BTW button).

## What was changed and why

Implemented all three changes called out in plan.md:

1. Created `teams/roles/interactive_debugger.md` — new long-running role that
   investigates a reported issue and pauses at logical checkpoints, writing
   `## Team: interactive-debug (claude)` + `## Debug Pause — Checkpoint <N>`
   payloads atomically (`.tmp` + rename) to
   `/workspace/.klodTalk/out_messages/debugger_message.txt`, then polls
   `/workspace/.klodTalk/in_messages/debug_reply.txt` every ~500 ms with a
   1800 s hard cap. Reserved replies are `continue` (advance) and `exit`
   (finalize); anything else is a free-form follow-up. The role refuses to
   modify source unless the user reply contains `fix it`, `apply`, or
   `make the change`. YAML frontmatter declares the filesystem MCP server
   pointed at `/workspace` (same pattern as `coder.md`). The file inherits
   the base conventions via `<!-- inherits: base.md -->` and includes the
   required malware-policy reminder.

2. Created `teams/teams/interactive-debug.md` — team definition with title,
   one-line description, `## enabled` H2 heading (per the team-disable-flag
   skill), a `## Members` table with the single `interactive_debugger` member
   on model `opus`, a single-step long-running `## Pipeline`, and a
   `## Special Rules` block enumerating: no code edits without explicit
   trigger phrase, pause only at meaningful checkpoints, channel files
   restricted to `debugger_message.txt` (out) and `debug_reply.txt` (in),
   reserved replies `continue`/`exit`, 4 KB caps on summary/evidence, 1800 s
   timeout.

3. Modified `server/server.py` `handle_btw` (around line 1457) to be
   team-aware. After the existing "session must be running" check, the
   handler now resolves the active team using the same precedence as
   `trigger_session_agent` and `handle_new_session`
   (`_session_team_override.get(session_id)` falling back to
   `get_project_record(session.project_name).get("team")`). If the active
   team is `interactive-debug`, the handler:
     - logs the reply to `history_store` and `session_log` as
       `user_debug_reply` with content prefix `[DebugReply]`,
     - broadcasts the user's message to session users via
       `_broadcast_to_session_users` with role=`user` and the
       `[DebugReply] <content>` prefix (so the user sees their own reply in
       the chat),
     - atomically writes `content` to
       `/workspace/.klodTalk/in_messages/debug_reply.txt` (`.tmp` + rename),
     - sends an `ack` to the websocket and returns early — `_run_btw_agent`
       is NOT spawned.
   For all other team values, the original BTW behaviour is preserved
   unchanged (the new branch is purely additive above the existing code).

## Known limitations

- The debug payload broadcast to clients depends on the existing
  `debugger_message.txt` -> client wiring; per the plan that wiring was
  declared already-in-place and explicitly out of scope for this change.
  If a future change needs to surface checkpoints in the web/Android
  clients, a debugger broadcast block (similar to the coder/idea blocks)
  would need to be added to `server.py` and the `TEAM_ROLES_SET` /
  Android `TEAM_ROLES` lists — but that is outside this task's scope.
- The role uses substring matching for the trigger phrases (`fix it`,
  `apply`, `make the change`); a user could in principle hit these by
  accident in a follow-up. The role's pause-after-change rule mitigates
  this.

## Round 2 fixes

Addressed the reviewer's BLOCKER plus the two cheap WARNINGs and the two
small SUGGESTIONs.

1. **BLOCKER — `debugger_message.txt` broadcast handler (server/server.py).**
   Added a dedicated handler block in `watch_out_messages` immediately after
   the `coder_message.txt` block (now around lines 1014-1045). The block
   mirrors the `coder_message.txt` template exactly:
     - builds the path via `os.path.join(message_folder, "debugger_message.txt")`,
     - reads + `os.remove`s the file with try/except logging,
     - resolves team via `_session_team_override.get(session_id, "")` with
       fallback to `get_project_record(session.project_name).get("team", "")`,
     - calls `history_store.append(session_id, workspace, "debugger", content,
       model=_models.get("debugger", ""))`,
     - calls `session_log.log_event(session_id, "debugger", content, model=...)`
       inside a try/except,
     - broadcasts via `_broadcast_to_session_users` with role `"debugger"` and
       the same field shape as the coder block.
   With this, the interactive-debugger checkpoint payloads now reach the user
   end-to-end. The `debugger` role is already known to both clients
   (`TEAM_ROLES_SET` in web, `TEAM_ROLES` in Android) so no client edits are
   needed.

2. **WARNING #1 — defensive try/except around team resolution in `handle_btw`.**
   Wrapped the `get_project_record` + override-precedence block (server.py
   ~lines 1479-1494) in `try/except`. On exception we log a warning and set
   `active_team_name = None`, which routes the BTW message through the
   original (non-debug) path. This bounds the blast radius of a misconfigured
   project so it cannot break BTW for unrelated teams.

3. **WARNING #2 — document the intentional history role.**
   Added a one-line comment above the `history_store.append(... "user" ...)`
   call in the interactive-debug branch explaining that the role string is
   deliberately `"user"` (with a `[DebugReply]` prefix) so the reply surfaces
   in the natural user-message stream for clients and replay, while
   `session_log.log_event` distinguishes it via the `"user_debug_reply"`
   event type. Did NOT change the history role string (Option A, as the
   reviewer requested).

4. **SUGGESTION — `teams/roles/interactive_debugger.md` polling instructions.**
   Replaced the ambiguous "`time.sleep(0.5)` in a Python loop, or `sleep 0.5`
   in a bash loop" sentence with an explicit Bash tool example:
   ```bash
   while [ ! -s /workspace/.klodTalk/in_messages/debug_reply.txt ]; do sleep 0.5; done
   ```
   and tightened "delete it (or truncate it to empty)" to
   "delete it (`rm /workspace/.klodTalk/in_messages/debug_reply.txt`)", as
   requested.
