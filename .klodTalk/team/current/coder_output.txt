#### Deviations from evaluated_ideas.md proposal
1. **planner.md**: evaluator suggested blocking `Write/Edit/MultiEdit/NotebookEdit`,
   but the Planner role MUST write `plan.md` and `plan_meta.txt`, and for SIMPLE
   tasks it implements code directly (see planner.md "For SIMPLE tasks: Implement
   directly"). Blocking Write/Edit would break both. Restriction narrowed to
   `MultiEdit, NotebookEdit` only. Rationale documented in the role's comment block.
2. **super_planner.md**: kept Write (needed for coder_output.txt) but blocked
   Bash/Edit/MultiEdit/NotebookEdit -- this matches the role's "Do NOT Write Code"
   contract and its "Do NOT commit" rule.
3. **documenter.md**: evaluator suggested blocking Bash, but the Documenter role
   explicitly performs a git commit step which requires Bash. Restriction narrowed
   to `MultiEdit, NotebookEdit` only; the operator-level
   `autoMode.hard_deny` (settings layer) remains the correct place for a stronger
   lock. Rationale documented in the role's comment block.
4. **debugger.md**: left unrestricted because the role legitimately needs Bash
   (to run tests / reproduce), Write/Edit (to add temporary debug prints), and
   only NotebookEdit could conceivably be blocked. Adding a frontmatter block
   that only blocks NotebookEdit was judged not worth the file churn; deferred to
   a future cycle if a notebook-relevant case emerges.

## Follow-ups / Known Gaps
1. The hook event summary step in orchestrator.md depends on the JSONL writer
   (post_tool_use_logger.sh) being registered for every role's container. That
   registration lives in `.claude/settings.json` which the orchestrator does NOT
   touch directly -- it is installed by `server/run_agent.py`. No code change is
   needed here (the hook is already registered), but if a future agent role is
   spawned without that hook, the summary will silently be a no-op.
2. The Tool Search beta header opt-in is documented but NOT yet wired into any
   container env. Wiring it requires editing `server/run_agent.py`, which is
   outside this task's allowed edit set. Tracked in the skill file's "Enabling"
   section.
3. The debugger.md and general.md roles intentionally received no frontmatter.
   Revisit if a security review flags this as a gap.
